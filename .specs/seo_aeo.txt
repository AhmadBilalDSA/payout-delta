================================================================================
SEO ARCHITECTURE OVERVIEW
================================================================================

Strategy: Static-first SEO; all metadata, structured data, and sitemaps are
          generated at build time. No server-side rendering for SEO signals.

Site URL: Defined in lib/seoSchemas.ts as SITE_URL constant.
Canonical form: {SITE_URL}/{route}/ (trailing slash enforced)
IndexNow: scripts/ping_indexnow.mjs pings Bing/Yandex on every build.

================================================================================
INTERNATIONALIZATION (i18n) GATES
================================================================================

File: lib/i18n/dictionaries.ts
Rule: ANY new UI string MUST be registered in this file before use.

Supported locales (7):
  en  — English          (LTR) [canonical]
  ur  — Urdu / اردو       (RTL)
  hi  — Hindi / हिन्दी    (LTR)
  fil — Filipino          (LTR)
  es  — Español           (LTR)
  pt  — Português         (LTR)
  ar  — Arabic / العربية  (RTL)

LANG_META export: { englishName, nativeName, shortLabel, isRTL } per locale
RTL enforcement: LanguageProvider.tsx sets document dir="rtl" for ur and ar

Dictionary structure:
  enStrings — canonical key set; all other catalogs must match keyof enStrings
  DICTIONARIES — Record<SupportedLang, UiCatalog>
  Vars type — interpolation variables ({curly} placeholders, replaced verbatim)

Preserved in all languages (not translated):
  Product names, provider identities, legal acronyms:
  PSEB, PRC, FEMA, FIRC, LUT, VAT, GST, P2P, corridor codes

================================================================================
CORE SEO RULES
================================================================================

1. Every page must have a unique <title> and <meta name="description">.
2. Canonical URLs always include trailing slash.
3. All images use next/image with unoptimized: true (static export).
4. No client-side navigation breaks crawlability — all routes are pre-rendered.
5. Structured data must be valid JSON-LD (validate with Google's Rich Results Test).
6. Any new route added to app/ must also be added to app/sitemap.ts.
7. Any new locale-specific content must add entries to LOCALIZED_CORRIDORS.
8. i18n strings must be registered in lib/i18n/dictionaries.ts before use.
